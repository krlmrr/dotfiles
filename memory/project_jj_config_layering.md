`~/.config/jj/conf.d/*.toml` layers on top of `~/.config/jj/config.toml` — verified on jj 0.43.0, both empirically and against `jj help -k config`. This is the assumption the whole jj identity design in this repo rests on: `jj/config.toml` is symlinked and committed (deliberately minimal — just `[ui] editor = "nvim"`), while `~/.config/jj/conf.d/00-identity.toml` is generated by `./configure` from `$GIT_NAME`/`$GIT_EMAIL` and never committed, because identity is machine-specific. See [[project_jj_colocate_index]] for the colocation gotcha found while setting this up.

**If a future jj version drops conf.d layering:** copy `jj/config.toml` to `~/.config/jj/config.toml` and append the identity block, instead of symlinking + a separate layered file. (Until v2.0.0 this pointed at `.gitconfig`'s copy-and-inject pattern as the precedent — that is no longer accurate: `.gitconfig` is now itself symlinked, with a generated `~/.config/git/identity` pulled in via `[include]`, i.e. the same shape as jj's conf.d rather than a copy.)

**Hook bypass (historical — no longer applies):** jj does not run git hooks, so `jj commit`/`jj describe` here used to silently skip `git/hooks/pre-commit`, which auto-sorted Brewfile entries. That hook was retired in v2.0.0 (it corrupted comment attribution by construction and its `sort` was locale-dependent), so there is no Brewfile auto-sort to bypass any more — the Brewfile is hand-ordered.
