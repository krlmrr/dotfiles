`~/.config/jj/conf.d/*.toml` layers on top of `~/.config/jj/config.toml` — verified on jj 0.43.0, both empirically and against `jj help -k config`. This is the assumption the whole jj identity design in this repo rests on: `shared/jj/config.toml` is symlinked and committed (deliberately minimal — just `[ui] editor = "nvim"`), while `~/.config/jj/conf.d/00-identity.toml` is generated by `./configure` from `$GIT_NAME`/`$GIT_EMAIL` and never committed, because identity is machine-specific. See [[project_jj_colocate_index]] for the colocation gotcha found while setting this up.

**If a future jj version drops conf.d layering:** fall back to the copy-and-inject pattern `.gitconfig` already uses in `./configure` — copy `shared/jj/config.toml` to `~/.config/jj/config.toml` and append the identity block, instead of symlinking + a separate layered file.

**Hook bypass:** jj does not run git hooks, so `jj commit`/`jj describe` in this colocated dotfiles repo silently skip `shared/git/hooks/pre-commit` (which auto-sorts Brewfile entries). Not a bug, just don't be surprised by an unsorted Brewfile after a jj-made commit — re-run the sort via a git commit, or sort by hand.
