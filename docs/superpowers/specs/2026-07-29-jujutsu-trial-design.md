# Jujutsu (jj) trial — design

**Date:** 2026-07-29
**Status:** approved, pending implementation

## Goal

Install Jujutsu (`jj`) and its TUI (`lazyjj`) through the dotfiles, with a minimal
shared config, and colocate `jj` into this dotfiles repo so it can be used on real
work without displacing git.

Colocation is the point: `.git` stays intact and authoritative, so git, lazygit and
the editors keep working unchanged. Backing out is `rm -rf .jj`.

## Non-goals

- No revset aliases, `ui.default-command`, or diff/merge tool wiring. The shared
  config stays near-empty; opinionated defaults can come later once the tool is
  actually understood.
- No Raycast script commands. This is terminal-native work.
- No changes to any repo other than this one.
- No `$EDITOR` export added to zsh. That would change git's behaviour too, which is
  outside this trial.

## Changes

### 1. Install — `shared/Brewfile`

Add two formulae, keeping the file's alphabetical order:

- `brew "jj"` (0.43.0) — after `imagemagick`
- `brew "lazyjj"` (0.6.1) — after `lazygit`

`shared/Brewfile` is used on both macOS and Linux, so no per-platform branch is
needed. Both formulae are in homebrew-core.

### 2. Shared config — `shared/jj/config.toml` (new, symlinked)

```toml
[ui]
editor = "nvim"
```

`nvim` rather than `zed --wait` deliberately. This setting only governs the
throwaway commit-message buffer (`jj describe`) — `jj split` and `jj diffedit` use a
separate *diff* editor that defaults to jj's built-in terminal TUI and is
unaffected. Keeping the message buffer in the terminal avoids a focus steal and,
more importantly, avoids spawning a short-lived Zed window that the yabai
editor-array logic in `external_correct`/`place_one` would try to place into the
trio layout.

Left unset, jj falls back to `$EDITOR`, which is not set on this machine, landing in
a nano-like editor.

### 3. Config delivery — `configure`

Symlinked, so edits to the source are live — matching nvim, lazygit and zed:

```bash
mkdir -p ~/.config/jj
link "$DOTFILES_DIR/shared/jj/config.toml" ~/.config/jj/config.toml
```

`~/.config/jj/config.toml` is the correct path on both macOS and Linux; jj uses XDG
paths on both.

### 4. Identity — generated, never committed

`jj` refuses to create commits without `user.name` and `user.email`. These are
person-specific and cannot live in the repo, which is the same constraint that makes
`configure` copy `.gitconfig` instead of symlinking it.

`configure` generates `~/.config/jj/conf.d/00-identity.toml` from the git identity it
already reads:

```toml
# generated by ./configure — do not edit
[user]
name = "…"
email = "…"
```

Written only when both git values are non-empty, so a fresh machine that has not yet
answered `setup`'s identity prompts does not get a half-written file. This keeps the
shared config symlinked and live-editable while the machine-specific part stays out
of git.

**Assumption to verify first:** that `conf.d/*.toml` layers on top of `config.toml`
rather than replacing it. Confirm with `jj config list --include-defaults` (and
`jj help config`) immediately after install, *before* wiring it into `configure`.
If jj treats them as either/or, fall back to the `.gitconfig` pattern — copy
`config.toml` to `~/.config/jj/config.toml` and append the `[user]` block — and
record that the config became a *copied* config, meaning edits need a `./configure`
re-run.

### 5. Aliases — `shared/zsh/aliases.sh`

A `# Jujutsu` block under the existing `# Tools` section:

```bash
alias lzj="lazyjj"
alias js="jj status"
alias jl="jj log"
alias jd="jj diff"
alias jn="jj new"
```

Deliberately minimal — `jj` is already two characters, so aliasing everything buys
little. `lzj` sits beside the existing `lzg`.

`.zshrc` is a **built** config: run `./buildzshrc` after editing.

### 6. Ignore + colocation

- Add `.jj/` to `shared/git/gitignore_global`, so no repo needs a local ignore entry.
  (`jj git init --colocate` does not touch `.git/info/exclude` — it writes its own
  `.jj/.gitignore` containing `/*`. The global entry is still what keeps `.jj/`
  out of git status for this repo and any repo colocated later.)
- Run `jj git init --colocate` in this repo.

## Verification

1. `brew bundle --file=shared/Brewfile` installs both formulae; `jj --version` and
   `lazyjj --version` report the expected versions.
2. `jj config list --include-defaults` shows `ui.editor = "nvim"` **and** the
   generated `user.name`/`user.email` — this is the check that proves the `conf.d`
   layering assumption in §4.
3. `./configure` is idempotent: run it twice, confirm the symlink and the generated
   identity file are both correct and unduplicated.
4. `./buildzshrc && source ~/.zshrc`, then confirm the aliases resolve.
5. In this repo after colocation: `jj st` and `jj log` succeed, **and** `git status`
   and `lazygit` still behave exactly as before — colocation must not disturb git.
6. `git status` does not show `.jj/` as untracked.

## Rollback

- `rm -rf .jj` — removes colocation entirely, leaves `.git` untouched.
- `brew uninstall jj lazyjj`.
- Revert the edits to `shared/Brewfile`, `configure`, `shared/zsh/aliases.sh`,
  `shared/git/gitignore_global`; delete `shared/jj/`; remove
  `~/.config/jj/`; re-run `./buildzshrc`.

Nothing in this change writes to `.git` or `~/.gitconfig`.
